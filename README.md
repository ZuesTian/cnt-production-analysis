# 碳纳米管生产数据分析系统

碳纳米管（CNT）生产线数据综合分析工具，支持 **L3** 和 **11A** 产线的炉子级统计、每日/月汇总、异常检测、故障分析和故障预警。

## 快速开始

### 方式一：打包版（推荐，无需 Python）

1. 下载 `dist/碳纳米管生产数据分析.exe`
2. 将生产数据 `.xlsx` 文件放在 exe 同目录下（软件会自动识别文件名含"生产数据"的文件）
3. 双击 exe 启动 GUI

### 方式二：源码运行

```bash
pip install -r requirements.txt
python gui_app.py
```

### 方式三：命令行

```bash
python analysis.py --all                                    # 全部分析
python analysis.py --furnace E01 E02 --daily --monthly      # 指定炉子
python analysis.py --anomaly                                # 异常检测
python analysis.py --fault-analysis --fault-warning         # 故障分析 + 预警
python analysis.py --list-furnaces                          # 列出所有炉号
python analysis.py --input 数据文件.xlsx --output 输出目录    # 指定输入输出
```

## 功能详解

### 1. 炉子级统计

**目标**：掌握每个炉子的生产效率和稳定性，识别高低两端表现。

**统计流程**：
1. 原始数据按「日期 + 炉号」合并白班/夜班为一次反应周期
2. 计算每个炉子每次周期的：反应时间、空烧时间、降清时间、故障时间、产率（产量 / 反应时间）
3. 按月分组，计算每个炉子的月平均指标
4. 对全区所有炉子按月算出各指标的平均值

**前后 20% 筛选**：
- 每月独立排名，取前 20%（优）和后 20%（差）
- 反应时间、空烧时间、降清时间、故障时间 → 越低越好（前 20% = 时间最短）
- 产率 → 越高越好（前 20% = 产率最高）
- 结果包含排名序号、所属月份、生产线、反应周期数

**输出文件**：`炉子级统计_全区.xlsx`
- Sheet 1「反应周期明细」— 每个炉子每次周期的完整记录（含来源工作表+行号追溯）
- Sheet 2「月度炉子平均」— 按月份+炉号的 5 项平均指标
- Sheet 3「全区各月平均」— 不区分炉号的全区月均值
- Sheet 4「前后20汇总」— 所有指标的排名汇总表
- 其余 Sheet — 每个指标独立的前/后 20% 列表

---

### 2. 每日汇总 + 趋势图

**目标**：追踪全区每天的生产运行状况。

**统计内容**（按日汇总）：
- 总产量（kg）
- 总反应时间（小时）
- 总故障时间（小时）
- 总空烧时间（小时）
- 总降清时间（小时）

**趋势图**：双面板布局
- 上图：柱状图展示总产量
- 下图：折线图展示四项时间指标，不同颜色区分

**输出文件**：`每日汇总.xlsx` + `每日趋势图.png`

---

### 3. 每月汇总 + 趋势图

**目标**：月度级别的生产运行纵览。

同每日汇总口径，按月聚合。适用于月度报告和对比分析。

**输出文件**：`每月汇总.xlsx` + `每月趋势图.png`

---

### 4. 单炉每日趋势图

**目标**：深入观察单个炉子的运行退化趋势，辅助预测性维护。

**每张图包含 4 层信息**：
| 图层 | 说明 |
|------|------|
| 柱状图 | 每日产量 |
| 产率折线（橙色） | 每日产率原始值 |
| 7 日均线（蓝色） | 产率的 7 日移动平均，平滑波动 |
| 线性趋势线（灰色虚线） | 产率随时间的变化斜率，标注日均变化量 |
| 异常标记（红叉） | 3σ 异常低产点 |
| 故障竖线（红色半透明） | 故障时间超过阈值的日期 |

**下部时间面板**：
- 反应时间（蓝）、故障时间（红）、空烧时间（橙）、降清时间（紫）
- 四线叠图，便于横向对比各类时间消耗

**输出文件**：`单炉每日趋势数据_全区.xlsx` + 每个炉子一张 PNG

---

### 5. 异常检测

**目标**：自动识别异常低产周期，追溯生产问题。

**检测逻辑（双阈值机制）**：

1. **3σ 原则**：按炉子分别计算产率均值 μ 和标准差 σ，标记低于 `μ - 2σ`（可配置）的周期
2. **最低产率阈值**：同时检查 `config.yaml` 中配置的 `min_yield_rate`（如 50 kg/h），低于该值的周期同样视为异常
3. 两种条件满足任一即标记为异常

**输出信息**（每条异常记录）：
| 字段 | 说明 |
|------|------|
| 日期、炉号、生产线、班组 | 异常周期定位 |
| 产量、产率 | 实际生产数据 |
| 产率均值、标准差 | 该炉子的正常基准 |
| 异常阈值 | μ - 2σ 计算值 |
| 偏差 σ | 偏离均值的标准差倍数 |

**输出文件**：`异常检测报告_全区.xlsx`
- Sheet「异常周期明细」— 所有异常记录的详细信息
- Sheet「炉号异常汇总」— 按炉号统计异常次数和最大偏差

---

### 6. 故障分析

**目标**：识别高频故障炉号、故障时间分布规律。

**故障排名表**：
| 指标 | 说明 |
|------|------|
| 故障总时间 | 统计周期内累计故障小时数 |
| 故障次数 | 出现故障的天数 |
| 故障天数 | 有故障记录的独立天数 |
| 平均故障时间 | 单次故障的平均时长 |
| 最大单日故障时间 | 最严重的一天 |

按故障总时间降序排列，一眼定位问题炉号。

**故障热力图**：
- 横轴 = 日期，纵轴 = 炉号
- 颜色深浅 = 故障时间长短
- 直观显示哪些炉子在哪些日期集中发生故障

**故障星期分布**：
- 按周一至周日统计故障次数和总时间
- 判断是否存在规律性的故障高发日

**输出文件**：`故障分析_全区.xlsx` + `故障热力图_全区.png`

---

### 7. 故障预警

**目标**：主动发现需要关注的故障风险，三级预警体系。

**预警类型 — 单日故障超阈值**：
- 统计每个炉子每天的故障时间
- ≥ `fault_warning_hours_per_day`（默认 8h）→ **预警级**
- ≥ `fault_critical_hours_per_day`（默认 12h）→ **严重级**

**预警类型 — 连续故障**：
- 检测同一炉子是否连续多天出现故障
- 连续天数 ≥ `consecutive_fault_days`（默认 2 天）→ **预警级**
- 记录连续故障的起止日期和区间内总故障时间

**预警类型 — 月累计故障超阈值**：
- 按月统计每个炉子的故障总时间
- 月累计 ≥ `monthly_fault_hours_warning`（默认 24h）→ **预警级**

**预警窗口**：
- 分析完成后自动弹出独立窗口
- 上半部分：预警汇总表（按炉号+级别统计）
- 下半部分：预警明细表
- 严重级 → 红色高亮底色
- 预警级 → 黄色高亮底色

**输出文件**：`故障预警_全区.xlsx`

**配置项**（`config.yaml`）：
```yaml
alert_thresholds:
  fault_warning_hours_per_day: 8     # 单日故障预警阈值（小时）
  fault_critical_hours_per_day: 12   # 单日故障严重阈值（小时）
  consecutive_fault_days: 2          # 连续故障天数阈值
  monthly_fault_hours_warning: 24    # 月累计故障阈值（小时）
  min_yield_rate: 50                 # 最低产率（kg/h），低于此值视为异常
  anomaly_sigma: 2.0                 # 异常检测 σ 倍数
```

## GUI 操作流程

### 1. 加载数据

- 软件自动识别目录中的 `.xlsx` 文件
- 也可点击「浏览」手动选择（支持 `.xlsx` / `.xls` / `.csv`）
- 点击「加载数据 / 刷新炉号」，顶部统计卡片显示数据概览

### 2. 选择炉号

- **全区炉子**：分析全部 147 个炉子（默认）
- **自选炉子**：列表点击选中（Ctrl/Shift 多选），或输入前缀（如 `E` = 所有 E 开头，`11A` = 所有 11A 开头）
- 选中后自动切换为自选模式，显示 "已选 X 个炉号"

### 3. 分析流程

1. 勾选需要的分析项
2. 点击「运行分析」→ 所有结果暂存内存，输出列表显示缓存摘要
3. 点击「导出报表」→ 一次性输出所有 Excel 文件到输出目录
4. 预览图表在「趋势图预览」Tab 中按需查看

### 4. 预览功能

- **每日/每月/故障热力图**：一键预览，纯内存生成
- **单炉趋势图**：从下拉框选炉子查看，或选中炉子后点「预览单炉趋势」
- 预览图随窗口大小自适应缩放
- 「输出文件」Tab 中双击文件直接打开

## 数据格式要求

输入 Excel 需包含以下列（列名可通过 `config.yaml` 自定义）：

| 源表列名 | 含义 | 数据类型 |
|----------|------|----------|
| 日期 | Excel 序列号或标准日期 | 数字 / 日期 |
| 班组 | 白班/夜班 | 文本 |
| 炉号 | 炉子编号（如 E01、11A17） | 文本 |
| 生产时间 | 反应运行时间（小时） | 数字 |
| 设备故障影响时间 | 故障停机时间（小时） | 数字 |
| 停机清理空烧 | 空烧/降清耗时（小时） | 数字 |
| 产量 | 产量（kg） | 数字 |
| 小时产能 | 产率（kg/h） | 数字 |

> 注意：当前「停机清理空烧」同时作为"空烧时间"和"降清时间"统计。如果源表后续拆分为两个独立字段，在 `config.yaml` 中增加映射即可。

## 配置文件

完整配置项见项目中的 `config.yaml`。以下为关键配置说明：

```yaml
# ── 数据列映射 ──
source_columns:
  date: 日期                    # 日期列名
  team: 班组                    # 班次列名
  furnace: 炉号                 # 炉号列名
  reaction_time: 生产时间        # 反应时间列名
  fault_time: 设备故障影响时间   # 故障时间列名
  clean_empty_burn_time: 停机清理空烧  # 空烧/降清列名
  output: 产量                  # 产量列名
  source_yield: 小时产能        # 源表产率列名

# ── 产线识别 ──
production_lines:
  L3:
    patterns: ["E", "F", "G", "H", "B"]   # 匹配这些前缀的炉号归为 L3
  "11A":
    patterns: ["11A"]                      # 匹配这些前缀归为 11A

# ── 排名设置 ──
ranking:
  top_percent: 0.2   # 前后百分比，设 0.2 = 20%

# ── 告警阈值 ──
alert_thresholds:
  fault_warning_hours_per_day: 8
  fault_critical_hours_per_day: 12
  consecutive_fault_days: 2
  monthly_fault_hours_warning: 24
  min_yield_rate: 50
  anomaly_sigma: 2.0
```

## 数据缓存机制

软件在以下环节使用缓存以提升性能：

| 缓存层 | 位置 | 内容 |
|--------|------|------|
| 清洗缓存 | `output/.cache/*.pkl` | 清洗并汇总后的反应周期数据，源文件变更时自动失效 |
| 分析缓存 | GUI 内存 | 运行分析后的所有统计结果，导出时批量写盘 |
| 预览缓存 | GUI 内存 | 图表以 BytesIO 生成，预览不写盘 |
